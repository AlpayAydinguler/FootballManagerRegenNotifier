The main fix: the app no longer gets stuck after misreading the year, or after loading a save more than about a year ahead. If you are on 0.1.0, please upgrade.

## Fixed

- **A misread year no longer stops the app for good.** In 0.1.0, a year misread into the past, such as 2025 read as 2013, was taken for a save reload and kept. Every correct reading after that looked like a jump of more than 400 days and was ignored, so the app went quiet and never alerted again. The same happened after loading a save more than about a year ahead. Now a jump of more than 400 days in either direction is held back. If the far-off date keeps reading the same way for about twenty seconds without the tracked date showing up again, the app switches to it. If it switched to the wrong one, it switches back the same way once the real date is read again, and reports anything crossed meanwhile.
- **A year misread by one is caught too.** 2025 read as 2026 is only 365 days, inside the 400-day limit, so 0.1.0 believed it and reported a year of intakes. A jump to the same date in another year, give or take a week, is now treated as a likely misread and waits the same twenty seconds.
- **Changing the game process name or the privacy options no longer needs a restart.** In 0.1.0 they only applied after restarting the app; now they apply the next time monitoring starts.
- **`fm.exe` works as the game process name.** In 0.1.0, `fm.exe` matched nothing and the app said Football Manager was not running. The field now accepts `fm`, `fm.exe` or a full path.
- **The preview keeps the last reading when sampling pauses.** With the default settings, switching to this window to check on it makes Football Manager inactive, and the preview used to blank its text, date and confidence. It now keeps the last reading and says it is paused.
- **A stale screen handle no longer leaves the capture blank.** When a capture comes back as one flat colour, the app now drops its screen handle and gets a fresh one on the next read. After a display change, for example, that turns a blank capture into a one-second blip instead of one that lasts until you restart. Exclusive fullscreen still cannot be captured.

## New

- **Reset date** in the header, for switching to a different save. Stop monitoring, load the other save, press **Reset date**, then start again. The app forgets the tracked date and adopts the next one it reads. It does not report the gap, and it announces any intake window open at that date. If you close the app before a date is read, the next run still starts fresh. It works while monitoring as well, but by the time you can press it the new save's date has usually been read already.
- **OCR confidence floors** on the Alerts & Options tab: **Minimum mean confidence** (55%) and **Minimum per-character confidence** (70%). These were fixed in 0.1.0. If the Activity Log shows dates rejected for confidence that look correct in the preview, lower them, or set both to 0. Change them while monitoring is stopped.
- **More in the Activity Log.** It now says when the capture comes back blank, when no date is found in the region, when the region cannot be read, and when reading resumes. When sampling pauses it says why and, if the game was not found, which process name it looked for. It also says when Football Manager is detected again. Each is logged once when it changes, not every second. A held-back jump shows how close it is to switching (`3/10`), and the switch itself is logged with the reason.

## Changed

- **A big jump back is no longer a reload straight away.** A move back of more than 400 days, or to about the same date a year earlier, now waits about twenty seconds before it is believed. Pressing Continue meanwhile loses nothing. Other reloads re-arm at once, as before.
- **Switching saves.** A save more than about a year away is switched to after about twenty seconds. Nothing is reported for the gap, and windows open in that save are announced. Going back to the save you most recently left, in the same session, picks up where it was, up to about two months on in game. Restarting the app or pressing **Reset date** forgets it. A save up to a year later still looks like a holiday and reports every intake in between as missed. To avoid that, use **Reset date** as described above. See [Switching between saves](https://github.com/AlpayAydinguler/FootballManagerRegenNotifier#switching-between-saves) in the README.
- **The saved date is checked against the screen.** After a restart, if the first date read is more than about a year from the one in `state.json`, the app switches to it after two matching reads instead of waiting twenty seconds.
- The repository has a GitHub Sponsors button. Nothing in the app changes.

## Upgrading from 0.1.0

- **Your settings and state carry over.** Both live in `%APPDATA%\FMRegenNotifier`, and 0.2.0 reads the 0.1.0 files as they are. The new confidence settings start at 55% and 70%, the same values 0.1.0 used.
- **A misread date in `state.json` corrects itself.** If 0.1.0 got stuck on, say, 2013, there is no need to delete anything. Once you start monitoring and 0.2.0 has read the real date twice, it switches to it. Nothing is reported for the gap, and any intake window open at the real date is announced. If the saved date is the right day in the neighbouring year, it waits about twenty seconds instead. If the saved year is behind the real one, that year's intakes are reported as missed. If you would rather start clean, press **Reset date** before you start monitoring.
- **If you edited `data/countries.xlsx`**, extract 0.2.0 over the old folder or copy that file across. It lives beside the exe and is only written when missing, so a new folder gets the built-in table. Your ticked countries are in `settings.json` and are kept either way.
- **Going back to 0.1.0** works: it ignores the new fields. Your confidence floors return to 55% and 70%, and a process name of `fm.exe` stops matching. Set it back to `fm` and restart. The misread-year problem returns.
